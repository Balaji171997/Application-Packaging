Two MTB (Package Builder, `Downloads\Application-Packaging\files`) conversion/reuse house-style rules the user confirmed 2026-07-30 (r218). MTB and GPF are SEPARATE codebases — these were applied to MTB ONLY (user: "come out of GPF, concentrate on MTB").

**1. Get-ADTApplication / Uninstall-ADTApplication preferred syntax = `-Name '<val>' -NameMatch WildCard`** — Name FIRST, then `-NameMatch` with a BAREWORD (unquoted) ValidateSet value (Exact/WildCard/Regex/Contains). Before: positional v3 `-WildCard '*X*'` came out `-NameMatch 'WildCard' -Name '*X*'` (NameMatch-first, quoted). Matches PSADT's own doc example `Get-ADTApplication -Name 'Adobe Acrobat Reader' -NameMatch 'Exact'` and the module ValidateSet `'Contains','Exact','Wildcard','Regex'`. Impl in `PSADT_V3toV4_Mappings.ps1`: mapping values unquoted (`'-WildCard' = "-NameMatch WildCard"`) + new `Set-AdtApplicationNameOrder` pass (called after `Add-AdtApplicationNameParam`) that rewrites any call having BOTH -Name and -NameMatch into canonical order+bareword (leaves -ProductCode / -Name-only / dynamic-value calls alone).

**Why:** team wants the single most-preferred v4 form everywhere, stable regardless of the v3 source form.

**2. Predecessor reuse — keep exactly ONE `Set-MTBReboot` per POST section, at the template's end position (after `Set-MTBDetectionKey`), inheriting the predecessor's comment state.** The template POST-INSTALL/POST-UNINSTALL ends with `##Handling for required reboot` + commented `#Set-MTBReboot`. On reuse the predecessor body (injected above the branding key) carries its OWN `Set-MTBReboot` → two reboot lines. Rule: drop the predecessor's standalone one; set the template placeholder's comment state from the predecessor's — predecessor LIVE → uncomment template line; predecessor COMMENTED (or none live) → keep `#`. Impl in `Build.ps1`: `Sync-MTBRebootSection` (per-section: last reboot = template placeholder, earlier ones = predecessor's, removed + orphan header cleaned) + `Sync-MTBReboot` (drives POST-INSTALL & POST-UNINSTALL via `$script:SectionMarkers`), called just before `Format-OutputScript` in `Build-PredecessorScript`. PRE-section live template reboots untouched.

**Why:** duplicated/misplaced reboot lines (one live from predecessor at top, one commented from template at bottom) looked wrong; team wants one reboot, at the end, honoring what the predecessor intended.
