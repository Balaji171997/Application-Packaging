Package Builder predecessor reuse (reusing a prior version's package as the template) has a presentable **review report** added 2026-06-24 (r132), because the team's objective is: reuse should automate almost everything and clearly flag the few unknowns an engineer must fill — easy for a layman to read.

**Design (Build.ps1 `Get-PredecessorReport` -> @{Done; Check}):**
- **Done** = what was changed AUTOMATICALLY. Each line is VERIFIED against the built script (e.g. only claim an installer swap when the NEW filename is actually in the output) — so the engineer can trust it. Covers: reuse + identity retarget, version swap (with occurrence count), installer/MST/ProductCode swaps, carried session settings (ProcToClose/FreeSpace/...), kept custom code sections, uninstall-previous, v4 scope fix.
- **Check** = the unknowns, in plain language with WHY — sourced from `Get-ScriptReviewFindings` (carried detection ProductCode, carried .inf/.iss answer file, v4 scope traps) + `Get-SourceWarning` (source structure/type mismatch).
- `Format-PredecessorReportText` / `Format-PredecessorReportHtml` render it; the HTML is a presentable standalone export ("Save report" button).

**GUI:** `Show-ReviewPopup` is the two-part report for reuse builds (green "Done automatically" over amber "Please check / fill"); the toolbar button reads "Reuse report (N)"; it auto-opens on the first reuse build. `State.ReusePkg` holds the built new-package facts (set in `Build-Step3Script`, cleared on Step-1 reset).

**How to apply / extend:** when you add a new auto-step to `Build-PredecessorScript`, add a matching VERIFIED Done line; when you add a new manual-attention case, add it to `Get-ScriptReviewFindings` (it flows into Check automatically). Never let a Done line claim something not provable from the built script. See [[verify-semantic-not-syntax]].

**Reuse Main-section logs — use predecessor's own, drop v4 template scaffold (GPF, r41, 2026-07-30):** team decision "during predecessor reuse use whatever the predecessor has and remove our v4 template log lines." `Build.ps1 Set-SectionBody` gained `-DropTemplateLogs`; `Build-PredecessorScript` passes it TRUE only for GPF Main sections (`MainInstallCode/MainUninstallCode/MainRepairCode`). It drops the template's `Write-ADTLogEntry "...$appVendor $appName $appVersion..."` Start/Installation-of scaffold, keeps the predecessor's OWN (already-v4-converted) logs verbatim — needed because iDEX predecessors log `"Installation finished successfully with: [$exitcode]"`/`"failed with"` which the `bodyOwnsAction` regex can't detect, so scaffold used to survive AND get doubled. After dropping, whitespace-only lines are blanked + blank runs collapsed, then kept scaffolding (UseDialogs block) + one blank line + predecessor body — dedicated return, fresh/owns-action paths untouched. EMPTY body → section stays PRISTINE (predecessor authored nothing, e.g. iDEX has no Repair). Reverted the earlier r40 `Set-GpfMainSuccessLog`-on-reuse attempt (that wrapped the body in two redundant logs). 11 ungated `NF reuse:` assertions in Test-Build (554 pass/0). Verified real end-to-end on `SecondtestCases\...iDEX...3.0.6.4\Predecessor\...3.0.0.0` (parse 0, 0 invisible chars, Remove-BrandingREG→Remove-Branding). See [[log-path-format-v4]].

**GPF fuzzy predecessor match (r42, 2026-07-30):** `Get-GpfPredecessorCandidates` (BrandGpf.ps1, scans the request's CURATED `Predecessor\` folder) rejected a hand-placed predecessor when its `Vendor_AppName` differed even slightly from the new package — old guard was an exact `-ine` compare, user saw "no predecessor". Now fuzzy: new `Get-GpfNameKey` (lowercase, alphanumerics-only), `Get-GpfLevenshtein`, `Test-GpfNameFuzzyMatch` (accept exact key OR substring-either-way OR Levenshtein similarity ≥ 0.82) — e.g. `PaloAltoNetwork`↔`PaloAltoNetworks`, `Animator4`↔`Animator 4`, `iDEX`↔`iDEXx64` all match; unrelated apps in the same folder still rejected. GPF-only (portable, no share). Test-Build 556/0.

**Snapshot-assisted reuse (r139, 2026-06-30):** if the engineer ALSO snapshots the new installer during a reuse build, `Build.ps1 Merge-SnapshotDeltas` (runs at the END of `Build-PredecessorScript`) ADDITIVELY merges the snapshot deltas WITHOUT touching the predecessor's install/uninstall/repair logic. Rules (user: "merge net-new only… freespace softident should get changed from snapshot info… if already similar there then not needed"): FreeSpace raised to the new footprint (max, never lowered); SoftIdent refreshed from `$NewPkg.SnapshotSoftIdent` only when the predecessor's is empty/placeholder/single-GUID (multi-GUID or expression detection left intact); ProcToClose/Block UNION in new app exes; cleanups appended to POST-INSTALL/UNINSTALL only when their target isn't already handled (`Get-CleanupTarget` dedup). Snapshot-added lines are tagged `# [snapshot-added]`, refreshed detection `# [snapshot-detection]`; the report surfaces both. GUI stashes the snapshot detection/procs as `$newPkg.SnapshotSoftIdent`/`SnapshotProcs` in reuse (NOT SoftIdent/ProcToClose — those override/clobber). Per-user config still stays OUT of reuse (PerUserMode forced 'None' at the GUI); add per-user via snippets. Fresh builds are unchanged (auto-inject via `New-StandardCommands`).
